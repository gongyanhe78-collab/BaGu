数据库工程师软考 知识点总结
 一、数据库基础概念。

 1. 数据模型。

 - 概念数据模型：如 E - R 模型（实体 - 联系模型），包括实体、属性、联系
的概念。实体是现实世界中可区别于其他对象的“事物”或“对象”；属性是实体所
具有的某一特性；联系反映实体之间的关联关系，有一对一、一对多、多对多等类
型。

 - 逻辑数据模型：

 - 层次模型：以树形结构表示数据间的层次关系，有且只有一个根节点，根节点
以外的节点有且只有一个父节点。

 - 网状模型：用有向图结构表示实体和实体之间的联系，节点之间可以有多种联
系。

 - 关系模型：以二维表（关系）的形式组织数据，表中的行称为元组，列称为属
性。关系模型具有数据结构简单、操作方便等优点，是目前主流的数据库模型。

 2. 数据库系统结构。

 - 三级模式结构。

 - 外模式：也称子模式或用户模式，是数据库用户（包括应用程序员和最终用
户）能够看见和使用的局部数据的逻辑结构和特征的描述，是数据库用户的数据视
图，是与某一应用有关的数据的逻辑表示。

 - 模式：也称逻辑模式，是数据库中全体数据的逻辑结构和特征的描述，是所有
用户的公共数据视图。模式描述的是数据的全局逻辑结构，外模式通常是模式的子
集。

### 第 2 页

- 内模式：也称存储模式，是数据在数据库系统内部的表示，即对数据的物理结
构和存储方式的描述，包括数据的组织和存储方法、索引的组织和管理、数据压缩、
加密等。

   - 二级映像。

   - 外模式/模式映像：定义了外模式与模式之间的对应关系。当模式改变时（如增
加新的关系、改变关系的属性等），由数据库管理员对各个外模式/模式的映像做相应
改变，可以使外模式保持不变，从而应用程序不必修改，保证了数据的逻辑独立性。

   - 模式/内模式映像：定义了数据库全局逻辑结构与存储结构之间的对应关系。当
数据库的存储结构改变时（如选用了另一种存储结构），由数据库管理员对模式/内模
式映像做相应改变，可以使模式保持不变，从而应用程序也不必修改，保证了数据的
物理独立性。

   二、关系数据库理论。

   1. 关系代数。

   - 传统的集合运算。

   - 并（∪）：关系 R 和关系 S 具有相同的目 n（即两个关系都有 n 个属性），R∪
S 是由属于 R 或属于 S 的所有元组组成的集合。

   - 差（ - ）：R - S 是由属于 R 但不属于 S 的所有元组组成的集合。

   - 交（∩）：R∩S 是由既属于 R 又属于 S 的所有元组组成的集合，且 R∩S = R-
(R - S)。

   - 笛卡尔积（×）：设关系 R 为 m 元关系，关系 S 为 n 元关系，则 R×S 是一个 m
+ n 元关系，其中元组的前 m 个分量是 R 中的一个元组，后 n 个分量是 S 中的一个元
组。

   - 专门的关系运算。

```text
- 选择（σ）：从关系 R 中选择满足给定条件的元组，如σ条件(R)，条件可以是
比较表达式（如属性值大于某个值）或逻辑表达式（如多个条件的与、或关系）。

   - 投影（π）：从关系 R 中选取若干属性列组成新的关系，如π属性 1,属性
2(R)。

   - 连接（⋈ ）：从两个关系的笛卡尔积中选取属性间满足一定条件的元组。连接
运算有多种类型，如等值连接（连接条件为两关系中某些属性值相等）、自然连接
（是一种特殊的等值连接，它要求在结果关系中去掉重复的属性列）等。

   2. 函数依赖与范式。

   - 函数依赖。

   - 定义：设 R(U)是一个属性集 U 上的关系模式，X 和 Y 是 U 的子集。若对于 R(U)
的任意一个可能的关系 r，r 中不可能存在两个元组在 X 上的属性值相等，而在 Y 上的
属性值不等，则称“X 函数确定 Y”或“Y 函数依赖于 X”，记作 X→Y。

   - 范式。

   - 第一范式（1NF）：关系模式 R 的所有属性都是不可再分的基本数据项，则 R∈
1NF。

   - 第二范式（2NF）：若关系模式 R∈1NF，且每一个非主属性完全函数依赖于
码，则 R∈2NF。

   - 第三范式（3NF）：若关系模式 R∈2NF，且每一个非主属性既不部分依赖于码
也不传递依赖于码，则 R∈3NF。

   - BCNF（Boyce - Codd 范式）：关系模式 R∈1NF，若 X→Y 且 Y⊈ X 时 X 必含有
码，则 R∈BCNF。BCNF 是 3NF 的进一步规范化，消除了 3NF 中可能存在的主属性对码
的部分函数依赖和传递函数依赖。
```

### 第 4 页

1. 数据库设计的步骤。

  - 需求分析：通过调查用户的需求，包括数据需求、处理需求等，收集和分析用
户对数据库的各种要求，是数据库设计的基础。

  - 概念结构设计：主要采用 E - R 模型等概念数据模型来描述数据库的概念结
构，将用户需求抽象为信息结构，即概念模型。

  - 逻辑结构设计：将概念结构转换为关系模型等逻辑数据模型，包括确定关系模
式、属性、码等，并进行关系模式的规范化处理。

  - 物理结构设计：为逻辑数据模型选取合适的存储结构和存取方法，如确定数据
的存储位置、索引的建立等，以提高数据库的性能。

  - 数据库实施：包括创建数据库、加载数据、编写和调试应用程序等。

  - 数据库运行和维护：对数据库进行日常的管理、性能监测、故障恢复等操作。

  2. E - R 模型向关系模型的转换。

  - 实体转换为关系：一个实体转换为一个关系，实体的属性就是关系的属性，实
体的码就是关系的码。

  - 联系转换为关系。

  - 一对一联系（1:1）：可以将联系与任意一端实体所对应的关系合并，在关系中
加入另一端实体的码作为属性。

  - 一对多联系（1:n）：可以将联系与 n 端实体所对应的关系合并，在合并后的关
系中加入 1 端实体的码作为属性。

  - 多对多联系（m:n）：将联系转换为一个独立的关系，关系的属性包括联系本身
的属性以及与该联系相连的实体的码，关系的码是由相连实体的码共同组成的。

  四、数据库管理系统（DBMS）

### 第 5 页

1. DBMS 的功能。

   - 数据定义功能：提供数据定义语言（DDL），用于定义数据库的结构，如创建数
据库、创建表、定义视图、定义索引等。

   - 数据操纵功能：提供数据操纵语言（DML），用于对数据库中的数据进行操作，
如插入（INSERT）、删除（DELETE）、修改（UPDATE）和查询（SELECT）等操作。

   - 数据库的运行管理：包括对数据库的并发控制（解决多个用户同时访问数据库
时可能产生的冲突问题）、数据的完整性约束检查（确保数据的正确性和一致性）、
数据库的恢复（在数据库发生故障时恢复到正常状态）等功能。

   - 数据库的建立和维护功能：如数据库的初始数据装入、数据库的转储（备
份）、数据库的重组（提高性能）、数据库的性能监测等功能。

   2. 常见的 DBMS。

   - Oracle：是一款大型的、功能强大的关系型数据库管理系统，具有高可靠性、
高安全性、高性能等特点，广泛应用于企业级应用中。

   - MySQL：是一个开源的关系型数据库管理系统，具有体积小、速度快、成本低等
优点，适用于中小型网站和应用开发。

   - SQL Server：是微软公司开发的关系型数据库管理系统，与微软的操作系统和
其他软件产品有很好的集成性，在 Windows 平台上应用广泛。

   五、SQL 语言。

   1. 数据定义语句（DDL）

   - 创建数据库（CREATE DATABASE）：如 CREATE DATABASE database_name;

   - 创建表（CREATE TABLE）：例如 CREATE TABLE table_name (column1
datatype1, column2 datatype2,...);其中 column 为列名，datatype 为数据类型。

- 修改表结构（ALTER TABLE）：可以用于添加列（ALTER TABLE table_name ADD
column_name datatype;）、修改列的数据类型（ALTER TABLE table_name MODIFY
column_name new_datatype;）、删除列（ALTER TABLE table_name DROP COLUMN
column_name;）等操作。

   - 删除表（DROP TABLE）：DROP TABLE table_name;将删除指定的表及其所有数
据。

   2. 数据操纵语句（DML）

   - 插入数据（INSERT）：INSERT INTO table_name (column1, column2,...)
VALUES (value1, value2,...);将指定的值插入到表中的相应列中。

   - 查询数据（SELECT）：SELECT column1, column2,... FROM table_name WHERE
condition;用于从表中选择满足条件的列和行。可以使用各种函数（如聚合函数
SUM、AVG、COUNT 等）进行数据统计和分析。

   - 修改数据（UPDATE）：UPDATE table_name SET column1 = value1, column2 =
value2,... WHERE condition;用于修改表中满足条件的行的列值。

   - 删除数据（DELETE）：DELETE FROM table_name WHERE condition;用于删除表
中满足条件的行。

   3. 数据控制语句（DCL）

   - 授权（GRANT）：GRANT privilege ON object TO user;用于授予用户对某个对
象（如数据库、表等）的某种权限（如 SELECT、INSERT、UPDATE 等权限）。

   - 收回权限（REVOKE）：REVOKE privilege ON object FROM user;用于收回用户
对某个对象的某种权限。

   六、数据库的安全与保护。

   1. 数据库的安全性。

### 第 7 页

- 用户认证：通过用户名和密码等方式验证用户的身份，确保只有合法用户能够
访问数据库。

  - 权限管理：根据用户的角色和需求，授予不同的权限，如对表的读、写、修改
等权限，防止用户进行越权操作。

  - 视图机制：通过创建视图，可以隐藏表中的部分数据，只向用户展示他们需要
的数据，从而提高数据的安全性。

  2. 数据库的完整性。

  - 实体完整性：通过定义主码（主键）来保证实体的完整性，主码的值在关系中
是唯一的且不能为空。

  - 属性完整性：通过定义数据类型、取值范围（如使用约束条件 CHECK）等方式
来保证属性值的正确性。

  - 参照完整性：在关系数据库中，通过定义外键来保证参照完整性。外键是一个
表中的属性或属性组，它的值参照另一个表（称为参照表）的主码的值。

  3. 数据库的并发控制。

  - 并发操作带来的问题：如丢失更新（两个事务同时对同一数据进行更新，后一
个更新覆盖了前一个更新的结果）、不可重复读（一个事务在两次读取同一数据期
间，另一个事务对该数据进行了修改，导致第一次读取的数据与第二次读取的数据不
一致）、脏读（一个事务读取了另一个未提交事务修改的数据）等。

  - 并发控制技术：

  - 封锁技术：包括排他锁（X 锁，用于写操作，一个数据对象被加了 X 锁后，其
他事务不能再对该对象加任何锁）和共享锁（S 锁，用于读操作，一个数据对象被加
了 S 锁后，其他事务可以对该对象加 S 锁，但不能加 X 锁）等。

  七、数据库性能优化。

  1. 查询优化。

  - 合理使用索引：索引可以加快数据的查询速度，但过多的索引会增加数据更新
的开销。选择合适的列创建索引，如经常用于查询条件、连接条件的列。

  - 优化查询语句：避免使用复杂的嵌套查询，可以将其转换为连接查询等更高效
的查询方式；合理使用聚合函数，避免不必要的全表扫描等。

  2. 数据库结构优化。

  - 合理设计表结构：遵循关系数据库的设计范式，减少数据冗余；合理划分表，
如将经常一起查询的列放在一个表中，将不经常使用的数据分离到单独的表中。

  - 适当使用存储过程和视图：存储过程可以将复杂的业务逻辑封装在数据库端，
减少网络传输和提高执行效率；视图可以简化复杂的查询操作。

  3. 数据库物理存储优化。

  - 选择合适的存储引擎：不同的数据库存储引擎有不同的特点，如 MySQL 中的
InnoDB 适合事务处理，MyISAM 适合查询密集型应用。

  - 数据分区：对于大型数据库，可以将数据按照一定的规则进行分区，如按照时
间、地域等，提高查询效率和数据管理的便利性。
